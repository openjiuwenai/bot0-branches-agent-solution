# 外部系统和证据规则

外部系统包括网页、API、数据库、内网系统、文件下载、登录后页面和第三方服务。

默认把外部交互写成稳定的业务 SOP：入口、输入、输出、凭据/网络前置条件、失败
处理和人工复核。只有用户明确要求导出的 Skill 在运行时执行自动化交互，并且该
流程安全、受控、可复用时，才创建 `generated-skill/scripts/` 运行入口。

## 前置条件

可以写明登录、权限、验证码、内网、凭据和写操作确认，但当前环境无法证明的能力
不能写成已经通过。推荐表达：

- “需要用户提供可访问 URL、凭据或内网环境。”
- “外部系统可达时执行采集；阻断时返回需复核并保留原因。”
- “写操作执行前必须获得用户确认。”

## 运行脚本

如果最终 Skill 确实包含外部采集脚本：

- 输入参数、输出 schema、超时和失败行为必须稳定；
- 404、登录、验证码、权限或导航失败时停止当前目标处理，不能复用上一页数据；
- 输出业务结论所需的来源、覆盖情况和阻断原因；
- 文档、依赖清单和实际入口保持一致；
- 截图等可选文件只能引用当次运行真实生成的安全相对路径。

证据不足时可以保留局部计算结果，但必须标记为部分结果或需复核，不能输出无条件
的风险等级、审批结论或成功声明。
