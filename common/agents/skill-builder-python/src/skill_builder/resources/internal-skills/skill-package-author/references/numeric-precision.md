# 数值精度和确定性计算

规则越脆弱、越容易错、越需要一致性，越应该脚本化。

## 适用范围

包括金额、价格、报价、费用、税费、利息、汇率、数量、重量、面积、费率、百分比、评分权重、阈值比较、合计、均值、占比和风险分级。

## 计算规则

- Python 使用 `Decimal`；其他语言使用等价精确十进制 API 或最小整数单位。
- 从字符串构造 Decimal，不从 float 构造。
- 明确单位、精度、取整模式和展示格式。
- 按材料或 HITL 确认统一 `quantize`/取整。
- 合计值由已量化的明细组件计算。
- 不要用二进制 `float` 加 `round()` 生成最终业务数值。
- 如果材料与人工确认仍缺少会影响业务结论的数值边界、开放区间、取整、权重重分配、阈值包含性或缺失值处理，不得自行补默认值；应隔离受影响能力并标记未确认。

## 缺失和 N/A

区分“已观测到的业务缺失”和“未知/未采集”。

- 业务规则定义 0、空列表、无记录、无匹配项时，按规则处理。
- 采集失败、字段无法解析、页面不可达或证据不足时，才标记 N/A、排除权重或待复核。
- N/A 维度参与权重重分配时，报告要分开展示原始权重和有效权重，或把被排除维度显示为 `N/A`、`0%`、`excluded`。

## 报告列名和数据来源

- 评分、评级、风险矩阵或排名报告必须把“原始值”和“得分/评级”分开。表头是原始字段名时填原始值；表头是得分时必须包含 `得分`、`评分`、`score` 等字样。
- 最终报告、报价单、摘要或巡检结果必须通过显式参数读取当前运行的结构化数据，不要隐式扫描同目录旧文件或历史 sidecar JSON/CSV。
- 如果同一报告同时展示原始值和得分，使用两列，例如 `Star原始值` 和 `Star得分`，不要用 `Star` 承载得分。
