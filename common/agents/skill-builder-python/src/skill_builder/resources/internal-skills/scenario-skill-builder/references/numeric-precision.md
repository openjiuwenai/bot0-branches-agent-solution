# 数值精度规则

当确定性逻辑处理精确数值时，必须使用可复现的十进制或整数单位计算，不要使用二进制浮点数生成最终业务结论。

## 适用范围

包括但不限于：

- 金额、价格、报价、费用、税费、利息、汇率。
- 数量、重量、面积、体积、能耗、库存、百分比、费率、评分权重。
- 阈值比较、排名、合计、均值、占比、风险分级。

## 脚本要求

- Python 使用 `Decimal`；其他语言使用等价精确十进制 API 或最小整数单位。
- 从字符串构造 Decimal，不从 float 构造。
- 明确单位、精度、取整模式和展示格式。
- 按材料或 HITL 决策统一 `quantize`/取整。
- 合计值由同一批已量化明细计算，不能让明细和合计使用不同精度。
- 最终业务输出不要用 `float` + `round()`。
- 材料没有明确数值边界、开放区间、取整、权重重分配、阈值包含性或缺失值处理，且会影响业务结论时，把完整用户选择写入 `conflicts`，不生成 decisionId。平台编译稳定标识并展示统一 HITL；用户跳过时保留 pending/not_verified。

## 报告要求

- 数值缺失、未采集、不可解析、被阻断要区分展示。
- 如果 0、空列表、无记录、无匹配项是业务定义的观测缺失，按业务规则处理；只有采集失败或证据不足才写 `N/A`、排除权重或待复核。
- N/A 维度参与权重重分配时，报告要分开展示原始权重和有效权重，或把被排除维度显示为 `N/A`、`0%`、`excluded`。
- 评分/评级类报告必须区分原始指标和得分。表头写 `Star`、`金额`、`数量`、`汇率` 等原始字段时，单元格必须填原始值；填评分时表头必须写 `Star得分`、`金额得分`、`评分`、`维度得分` 等明确字段。
- 最终用户报告必须由同一次运行的结构化输入生成。不要让报告脚本自动扫描同目录旧 JSON、旧 CSV 或历史 sidecar 文件；所有输入必须通过显式参数传入。
