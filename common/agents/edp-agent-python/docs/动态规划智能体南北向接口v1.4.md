## 一  接口介绍

### 1.1 基本架构和本文档定义的内容

动态规划智能体接受业务应用的请求，处理并返回处理结果。

本文档定义了业务应用和动态规划智能体之间的接口协议。

### 1.2 动态规划智能体北向接口协议

本文档是在原有的基础上进行扩展，以便支持动态规划智能体接受应用的请求，并响应输出。

本协议是在基于的项目：通过Agent网关，将相关请求发送给Agent高代码。Agent对用户请求进行处理，当需要调用Agent低码时将调用Agent低码实现对应的功能。

#### Agent网关调用高码Agent接口定义

- **URI**：/v1/{project_id}/agents/{agent_id}/conversations/{conversation_id}
- **请求参数**：将原Agent接口请求参数，原样添加至动态规划智能体接口请求参数
- **响应参数**：将原Agent接口响应参数，原样添加至动态规划智能体接口响应参数

### 1.3 动态规划智能体南向接口协议

动态规划智能体直接拉起子工作流，工作流的返回可在动态规划智能体，进行动态规划以及前端交互，实现多工作流的灵活组合与高效协同，提升开发效率并降低运维成本

#### 1.3.1 直调工作流

**直接工作流请求URL结构**

```
http://{host}:{port}/v1/{project_id}/workflows/{workflow_id}/conversations/{conversation_id}?workspace_id={workspace_id}
```

**URL参数说明**

| 参数名 | 参数类型 | 是否必填 | 说明 |
|--------|---------|---------|------|
| host | String | 是 | 服务主机地址 |
| port | String | 是 | 服务端口号 |
| project_id | String | 是 | 项目ID |
| workflow_id | String | 是 | 工作流ID |
| conversation_id | String | 是 | 会话ID |
| workspace_id | String | 是 | 工作空间ID（Query参数） |

**请求头（Header）参数说明**

| 参数名 | 是否必填 | 说明 |
|--------|---------|------|
| stream | 是 | 是否启用流式输出，值为true或false |
| Content-Type | 是 | 内容类型，固定值：application/json |
| Accept | 否 | 接受的响应类型，通常为：*/* |
| X-PROJECT-ID | 是 | 项目ID，需与URL中的project_id保持一致 |
| cust-token | 是 | 客户认证令牌，用于身份验证 |
| X-USER-ID | 是 | 用户ID |

###### 动态规划智能体请求BODY体

| 参数名 | 参数类型 | 参数说明 |
|--------|---------|---------|
| query | Str | 用户提问的问题 |
| inputs | Map<String,Object> | 在调用工作流接口时，inputs对象中的字段（Key）并非API预留的固定字段，而是取决于您在工作流"开始节点"中定义的变量名 |
| plugin_configs | Array of PluginConfig objects | 插件配置信息：plugin_id：插件ID；config插件信息 |

###### 响应参数

| 参数名 | 参数类型 | 参数说明 |
|--------|---------|---------|
| event | String | 运行时最终输出内容表示运行时结果 |
| data | object | 运行时回复内容 |
| Create_time | Integer | 创建时间 |

###### Data参数明细

| 参数名 | 参数类型 | 参数说明 |
|--------|---------|---------|
| text | Str | 运行时输出内容消息块 |
| node_type | Str | 工作流节点类型 |
| node_id | Str | 节点ID |
| node_name | Str | 节点名称 |
| workflow_id | Str | 工作流ID |
| workflow_name | Str | 工作流名称 |

#### 1.3.2 控制器

动态规划智能体不直接对接工作流，通过拉起工作流封装后的上层控制器，无需关注底层工作流的分发，在接受到工作流的返回可在动态规划智能体，进行动态规划以及前端交互。**需要关注与工作流直调的输入参数的区别，要保证intent的传入**

接口调用说明

**请求URL结构**

```
http://{host}:{port}/v1/{project_id}/agents/{agent_id}/conversations/{conversation_id}?type=controller&workspace_id={workspace_id}
```

**URL参数说明**

| 参数名 | 参数类型 | 是否必填 | 说明 |
|--------|---------|---------|------|
| host | String | 是 | 服务主机地址 |
| port | String | 是 | 服务端口号 |
| project_id | String | 是 | 项目ID |
| agent_id | String | 是 | 智能体ID |
| conversation_id | String | 是 | 会话ID |
| type | String | 是 | 类型标识，固定值：controller |
| workspace_id | String | 是 | 工作空间ID |

**请求头（Header）参数说明**

| 参数名 | 是否必填 | 说明 |
|--------|---------|------|
| Accept | 否 | 接受的响应类型，通常为：*/* |
| Content-Type | 是 | 内容类型，固定值：application/json |
| stream | 是 | 是否启用流式输出，值为true或false |
| X-PROJECT-ID | 是 | 项目ID，需与URL中的project_id保持一致 |
| X-USER-ID | 是 | 用户ID |
| cust-token | 是 | 客户认证令牌，用于身份验证 |

## 二  接口说明

### 2.1 概念定义

| 概念 | 定义 |
|------|------|
| Converstion_id | 会话的唯一标识，同一个上下文会话过程记录在同一个Converstion_id标识下。Converstion_id有调用者产生，动态规划Agent消费。当Agent发现一个新的Converstion_id时，将自动产生一个新的上下文会话数据结构。 |
| Think | 思考过程，对于思考模型是会产生 |
| Todolist | 针对用户Query进行规划时产生的任务列表 |
| Todo | todo是任务列表的一项 |
| Subtask | 任务下的子任务项 |
| Interrupt | 智能体运行中终端信息，以便应用补充信息。 |
| Tool | 工具列表，在执行任务中，可能会调用各种工具执行，比如工作流，MCP，Skill等。 |
| Customer | 用户自定的其他信息 |
| final_answer | 任务执行的总结信息。 |

### 2.2 设计原则

三段式结构，所有消息类型都遵循三段式结构：

```
┌─────────┐     ┌────────────┐     ┌──────────┐
│ *_start │ --> │ *_stream/*  │ --> │  *_end   │
│ (开始宣告) │     │ (过程推送)   │     │ (结束确认)  │
└─────────┘     └────────────┘     └──────────┘
```

#### 3.1.2网关返回给前端WEB界面的返回信息

响应参数为流式，样例为：

```
data: {"type": "message", "data": {"content": "<think>"}, "nodeId": "node_1753063225350", "riskDescription":null}, "finish":false}
data:{"type":"text","data":{"content":"\n","nodeId":"node_end","riskDescription":null},"finish":false}
```

| knowledgeBaseSearch | 知识库检索标识                                               |
| toolCall            | 插件调用标识                                                 |
| parameter           | 调用插件时，抽取的参数                                       |
| observation         | 调用插件时，插件 functioncall 返回的结果                     |

### 3.2 事件示例---账户余额查询工作流
