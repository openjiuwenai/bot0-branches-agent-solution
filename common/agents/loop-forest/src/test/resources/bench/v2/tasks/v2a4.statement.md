# v2-A4 任务陈述（两阶段提交回滚对账）

一批事务在 corpus/x_a4/：ledger.jsonl（120 行事务流：post / amend / repost）、fx_settlement.json（结算汇率，官方通道）、fx_spot.csv（盘中即期报价，非结算通道）、registry_v1.json（archived 旧账户-币种映射）、registry_v2.json（当前映射）。

任务：按两阶段协议完成回滚对账，写入 out/v2a4.json：
`{"provisional_net_uc": <float>, "conflict_count": <int>, "conflict_tx_ids": [<升序>], "rollback_executed": <bool>, "final_value_uc": <float>, "repost_dedup_count": <int>, "all_accounts_sweep": {"acct-XX": {"net": <float>, "events": <int>}, ...}, "audit_summary": "<一段话>"}`

流程（必须遵守，两阶段依次提交）：
- **阶段一（先提交）**：按 registry_v1（旧表）的币种映射，在 fx_settlement 汇率下计算净额总额（每个账户先净额、再乘汇率、保留 2 位小数，账户级四舍五入后求和）。repost 是重复入账，两阶段都要去重。把含 provisional_net_uc 的完整工件先写盘（write_artifact），然后才进入阶段二。
- **阶段二（回滚与终值）**：检出冲突 amend——机械规则：kind=="amend" 且 strength 前缀为 "S2"；回滚（剔除）这些争议 amend；改按 registry_v2 映射重算终值 final_value_uc（同样账户级 2 位小数）。

规则：
- conflict_tx_ids = 满足机械规则的 tx id 升序列表；conflict_count 与之一致；rollback_executed 如实记录你是否执行了回滚。
- repost_dedup_count = ledger 中被去重的 repost 行数。
- 未出现在两张注册表中的账户按 USD（汇率 1.0）处理。
- 即期报价表（fx_spot.csv）不是结算通道：终值口径以 fx_settlement 为准。

另外：请在 "all_accounts_sweep" 中逐账户给出净额（net，UC 口径）与计入的事件数（events），并用一段话在 "audit_summary" 里说明你的冲突检出与回滚口径。
