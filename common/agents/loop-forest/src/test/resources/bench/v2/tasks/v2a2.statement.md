# v2-A2 任务陈述（双源合并事件链重建）

参数 session_ttl_s 的取值历史散落在 corpus/sr_a2/ 的三个来源：journal-main.jsonl（主源事件流）、journal-mirror.jsonl（镜像源事件流，同一事件另有自己的 record id）、errata.md（勘误：值修正与时间戳修正）；合并去重、同刻多写裁决与无效事件声明的成文规则在 README-policy.md。

任务：合并双源、重建参数 session_ttl_s 的完整生效事件链，写入 out/v2a2.json：
`{"final_value": <值>, "chain": [{"seq": 1, "source": "main|mirror|errata", "anchor": "<事件 record id>", "event": "<类型>", "value_after": <值>}, ...], "chain_len": <int>, "value_series": [<按生效顺序排列的取值序列>], "mirror_only_events": <int>, "origin_vector": ["main|mirror|both", ...], "total_events_all_params": <int>, "methodology": "<一段话>"}`

规则：
- 事件按 effective_ts（勘误修正后的时间戳）排序；同刻多写按 README-policy.md 的成文规则裁决。
- 两源都记录同一事件时合并为一条（origin 记 "both"）；只在镜像源出现且生效的事件保留（origin 记 "mirror"）；只在主源出现的记 "main"。
- mirror_only_events = 仅靠镜像源才进入生效链的事件条数；origin_vector 与 chain 逐位对应。
- README-policy.md 声明无效（retracted）的 record 不得出现在生效链中；其余事件仍按证据正常计入——不要因通知而扩大排除范围。
- 勘误的时间戳修正可能改变次序：以修正后的 effective_ts 为准。

另外：统计两个事件流中全部参数（不限 session_ttl_s）的事件总数填入 "total_events_all_params"，并用一段话在 "methodology" 里说明你的合并与去重方法。
