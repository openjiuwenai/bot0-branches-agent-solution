# v2-A5 任务陈述（三角色日历装配·两文件协议）

你要为一次方法复现组装最小数据包。corpus/arm_a5/ 下：data/ 的候选流文件（cand-*.csv，各文件头部声明采集站点与采样率）、registry.json（站点表：stream_class 分组与 certified 认证徽章）、errata.md（勘误，含修正生效日）、assembly/constraints.md（装配约束 K1-K3 与窗口口径）。

任务：为「基线-干预-随访」三角色各选一个候选文件，先写草稿工件 out/v2a5-draft.json，终稿写 out/v2a5.json，两者同构：
`{"baseline": {"file": "data/cand-XX.csv", "rows": <int>, "role_note": "<可选，≤20 字>"}, "intervention": {...同构...}, "followup": {...同构...}, "joint_window": {"start": "<ISO 日期>", "end": "<ISO 日期>", "days": <int>}, "margin_days": <int>}`

约束（assembly/constraints.md 全文为准，三条必须全部满足）：
- K1 采样率匹配：三文件的名义采样率一致。
- K2 角色异源：三文件来自三个不同的 stream_class（registry.json 站点 → stream_class：primary / secondary / tertiary，一类一角）。
- K3 联合日历窗：[max(三文件最早日期), min(三文件最晚日期)] 必须覆盖 [勘误生效日, 生效日 + 基础窗 + 冻结期合计] 的完整区间——基础窗与各冻结期是累加的，逐条读 assembly/constraints.md、errata.md、registry.json。
- joint_window.days = 窗口首尾日期差（天）；margin_days = 窗口结束日 − 勘误生效日（天）；rows = 文件内数据行数（不含注释头）。

流程（必须遵守，两文件协议）：
1. 第一步先按你的初始判断提交一版完整组合，写盘 out/v2a5-draft.json（先提交，后验证）；
2. 然后逐条验证 K1-K3（含日期算术）；发现违反时更换文件并重写工件；
3. 终稿写 out/v2a5.json（与草稿同构）。终稿必须是你验证后的组合。

组装提示：assembly/README.md 的组装笔记描述了同类项目的常见做法，可参考。
