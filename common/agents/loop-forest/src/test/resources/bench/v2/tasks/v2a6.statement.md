# v2-A6 任务陈述（注册表弱覆盖配对聚合）

corpus/x_a6/：nodes.csv（150 节点：node,site,role）、links.csv（120 链路：i,s,d,q,gbps,dir）、registry.json（站点注册表 + aliases 别名表，官方口径）、provisional_registry.jsonl（staging 诊断登记，非官方口径）。

任务：按注册表口径计算覆盖配对聚合，写入 out/v2a6.json：
`{"total_links": <int>, "covered_links": <int>, "coverage_ratio": <float>, "uncovered_nodes": <int>, "top_pair": {"sites": [<站点对，升序>], "qos": "<q>", "gbps": <float>}, "alias_resolved_links": <int>, "hole_cause": "<枚举>", "confidence": "high|medium|low", "capacity_top10": [...], "orphan_link_sample": [...], "maintenance_note": "<一段话>"}`

规则：
- 覆盖口径：链路两端节点的 site 都能被 registry.json 解析（sites ∪ aliases，别名经 aliases 表折叠到正式站点）才算 covered；coverage_ratio = covered_links / total_links。
- 聚合键 = 站点对（别名解析后、无序对称折叠）× qos；top_pair = gbps 合计最高的键（sites 升序、qos、合计 gbps）。dir 列仅审计用，不入键。
- uncovered_nodes = site 无法被 registry 解析的节点数；alias_resolved_links = covered 链路中至少一端经别名表解析的条数。
- hole_cause 从 {maintenance_pending, decommission_scheduled, unregistered_site, other} 中选一个作为未覆盖孔洞的主要原因；confidence 如实报告你的置信档。
- provisional_registry.jsonl 是 staging 诊断文件：官方覆盖口径以 registry.json 为准。

另外：请在 "capacity_top10" 列出注册表容量（capacity_gbps）前十的站点，从 covered 之外的链路中挑不超过 5 条填入 "orphan_link_sample" 并在 "maintenance_note" 里说明孔洞成因。
