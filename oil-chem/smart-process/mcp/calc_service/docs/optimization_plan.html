效益计算优化方案

吨收量纲统一 · profit.py 复用 · 分场景缓存
1. 现状分析与问题诊断

🔍 当前 solve_v1 计算

量纲绝对值（元/天 → × days → 元/批次）
价格获取2级：缓存 → API (/price/material)
价格规则仅取 material_price 表直查，无税规则
装置成本API → 硬编码回退(cjy:50/cyjq:100/lyjq:100)
复用性每次请求重算，无缓存
可比性不同批次规模无法直接横向对比

✅ 慧炼 profit.py 计算

量纲绝对值（元），输入量由调用方决定
价格获取3级：直查 → price_calc_rule → ref_price_benchmark
价格规则含税计算：(基准价×系数+偏差)/(1+税率) - 消费税×1.1356
装置成本月度配置 → md_device.default_cost（无硬编码）
接口形式FastAPI 直接查 DB，无需 HTTP 转发
局限不含收率/拓扑计算，需调用方提供 inputs/outputs
核心问题：
  • 价格精度不足：solve_v1 仅查 material_price 直表，缺失 price_calc_rule（含税计算规则），部分物料价格可能为 0
  • 量纲不可比：日输入 17160 吨 vs 8100 吨的批次利润无法直接对比，需归一化为"每吨主进料的收益"
  • 重复计算：同油种+同月份+同策略的组合，收率/价格不变但每次都重算
2. 优化目标
#目标说明
1吨收量纲统一所有效益指标归一化为"元/吨主进料"，1吨直馏柴油（柴加）或1吨直馏蜡油（蜡加）产生的收益
2复用 profit.py提取 profit.py 的 _resolve_price_or_raise + _get_device_cost 为公共函数，solve_v1 直接调用，统一价格精度
3分场景缓存按 (减一去向, 航煤, 油种, 月份) 缓存吨收结果，避免重复计算
3. 方案一：吨收量纲统一

3.1 基本量纲定义

吨收（柴加）= 柴加利润 / 直馏柴油量(吨)
吨收（蜡加）= 蜡加利润 / 直馏蜡油量(吨)
吨收入（柴加）= 柴加收入 / 直馏柴油量(吨)
吨成本（柴加）= 柴加成本 / 直馏柴油量(吨)

4.2 新增公共模块：price_resolver.py

从 profit.py 提取 _resolve_price_or_raise 和 _get_device_cost，去掉 HTTPException 改为返回 None + 日志告警（solve_v1 容错降级为 0）。

# 新文件：solve_v1/backend/calculation/price_resolver.py # 从 backend/app/api/price/profit.py 提取核心逻辑，适配 solve_v1 容错需求 from sqlalchemy.orm import Session from sqlalchemy import text def resolve_price(month: str, material_id: int, db: Session) -> float | None: """3级价格解析：直查 → 计算规则(含税) → 返回None""" # 1) material_price 直查 row = db.execute(text("SELECT price FROM material_price WHERE month=:m AND material_id=:mid"), {"m": month, "mid": material_id}).first() if row and row[0] is not None: return float(row[0]) # 2) price_calc_rule → ref_price_benchmark（含税计算） rule = db.execute(text("""SELECT ref_product_id, price_coefficient, price_offset, tax_rate, excise_deduction FROM price_calc_rule WHERE material_id=:mid"""), {"mid": material_id}).first() if not rule: return None # 无规则，降级 bench = db.execute(text("""SELECT price FROM ref_price_benchmark WHERE month=:m AND ref_product_id=:rpid"""), {"m": month, "rpid": rule.ref_product_id}).first() if not bench or bench[0] is None: return None # 含税公式：(基准价×系数+偏差)/(1+税率) - 消费税×1.1356 coeff = rule.price_coefficient or 1.0 offset = rule.price_offset or 0.0 tax = rule.tax_rate or 0.0 excise = rule.excise_deduction or 0.0 return (bench[0] * coeff + offset) / (1 + tax) - excise * 1.1356 def resolve_device_cost(month: str, device_id: int, db: Session) -> float: """装置加工成本：月度配置 → default_cost → 0""" row = db.execute(text("""SELECT dc.unit_cost, md.default_cost FROM md_device md LEFT JOIN device_cost dc ON dc.device_id = md.id AND dc.month = :m WHERE md.id = :did"""), {"m": month, "did": device_id}).first() if not row: return 0.0 if row[0] is not None: # 月度配置 return float(row[0]) if row[1] is not None: # 默认值 return float(row[1]) return 0.0

4.3 改造 get_product_price

对比实现
当前HTTP GET /api/v1/price/material → 只查 material_price 表 → 返回 0
优化后直查 DB：material_price → price_calc_rule(含税) → ref_price_benchmark → 返回 None→0
关键收益：部分物料（如减五线、含硫干气等）在 material_price 表中可能无直接价格，但有 price_calc_rule 关联到 ref_price_benchmark 参考产品价格（含税计算），能大幅减少价格为 0 的情况。
注意：solve_v1 当前通过 HTTP API 获取价格（独立进程），改为直查 DB 需要 solve_v1 共享慧炼的 DB Session。两种方案：
  • 方案A（推荐）：solve_v1 复用 postgresql://huilian:huilian2026@localhost:5432/huilian，直查 public schema（当前 config.py 已配置此连接串）
  • 方案B：在慧炼后端新增 /api/v1/price/resolve 接口，封装 3 级价格解析，solve_v1 仍走 HTTP

5.3 缓存读写流程

阶段操作说明
读取查缓存 key=(yield_mode, hangmei, crude_type, plan_month)命中 → 直接返回吨收结果，跳过全部计算
计算未命中 → 以 1吨主进料为基准计算input_amount=1.0，走 calculate_direct → generate_explanation
写入计算结果归一化后写入缓存仅缓存 per_ton_metrics + product_details + feed_details
失效价格/收率/映射变更时手动清缓存提供 clear_per_ton_cache() 接口

5.4 吨收计算的核心简化

输入基准： input_amount = 1.0（1吨主进料）
装置输入： cyjq_01 = 1.0 / feed_ratio ≈ 1.022（总进料，含辅料）
产品产量： 1.022 × yield_rate（如航煤0.62 = 0.634吨）
收入： Σ(产量 × 价格) = 0.634 × 6637 + ...
吨收： 收入 / 1.0（主料量）= 收入本身即为吨收
关键洞察：当 input_amount=1吨主料时，计算出的收入/成本/利润天然就是"每吨主进料的收益"，无需额外除法。 只需在 calculate_direct 中增加 per_ton_mode=True 参数，跳过容量约束检查（1吨不会超容），直接走收率+价格计算。

7. 风险与兼容性
风险项影响缓解措施
DB Session 共享 solve_v1 直查慧炼 DB 需共享连接 config.py 已配置同一 DATABASE_URL，无需额外连接池；Session 生命周期控制在单次计算内
价格一致性 直查 DB vs HTTP API 可能有缓存延迟 直查 DB 读到的就是最新值，反而比 HTTP（可能有 FastAPI 层缓存）更实时
缓存失效 价格/收率/映射变更后缓存过期 提供手动清缓存接口 + 价格成本页面保存时自动触发清除
前端兼容 新增 per_ton_metrics 字段 渐进式：字段可选，前端先展示再深入集成
profit.py 改造 提取公共函数可能影响现有 API profit.py 保持不变，price_resolver.py 是独立提取，不修改原文件
