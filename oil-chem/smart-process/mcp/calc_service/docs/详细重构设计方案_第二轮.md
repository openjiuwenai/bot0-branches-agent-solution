#### 1.1 `_precompute_hangmei_yields(batches, hangmei_ctx, calc_ctx, logger) -> dict`

提取航煤预计算循环（每批次各主动/被动装置 effective_input 和收率）。

```python
def _precompute_hangmei_yields(
    batches: List[dict],
    hangmei_ctx: Optional[HangmeiContext],
    calc_ctx: Optional[CalcContext] = None,
    logger=None,
) -> dict:
    """预计算每批次航煤主动/被动装置的有效输入量和收率。

    返回:
        {batch_id: {active_eff: float, passive_eff: float,
                    active_yields: dict, passive_yields: dict}}
        若 hangmei_ctx 未启用或无航煤装置，返回空 dict。
    """
    if not hangmei_ctx or not hangmei_ctx.enabled:
        return {}

    result = {}
    for batch in batches:
        batch_id = batch.get('batch_id', '')
        bi = {
            'active_eff': 0.0,
            'passive_eff': 0.0,
            'active_yields': {},
            'passive_yields': {},
        }
        # 主动装置
        for dev_id in hangmei_ctx.active_device_ids:
            daily_input = batch.get('total_input', 0) / (batch.get('days', 1) or 1)
            eff = _compute_device_effective_input(
                None, daily_input, batch.get('mode', 'X_ZERO'), dev_id,
                hangmei_ctx=hangmei_ctx, calc_ctx=calc_ctx)
            bi['active_eff'] += eff
            for prod in hangmei_ctx.active_products:
                yr = _resolve_hangmei_yield(prod, batch.get('mode', 'X_ZERO'))
                bi['active_yields'][prod.id] = yr
        # 被动装置
        for dev_id in hangmei_ctx.passive_device_ids:
            daily_input = batch.get('total_input', 0) / (batch.get('days', 1) or 1)
            eff = _compute_device_effective_input(
                None, daily_input, batch.get('mode', 'X_ZERO'), dev_id,
                hangmei_ctx=hangmei_ctx, calc_ctx=calc_ctx)
            bi['passive_eff'] += eff
            for prod in hangmei_ctx.passive_products:
                yr = _resolve_hangmei_yield(prod, batch.get('mode', 'X_ZERO'))
                bi['passive_yields'][prod.id] = yr
        result[batch_id] = bi
    return result
```

**替换点**：
- `evaluate_combination` L1029-1075 → 调用 `_precompute_hangmei_yields(...)`，结果存入 `hangmei_precompute` dict
- `recompute_combination_economics` L1567-1600 → 同上

#### 1.2 `_apply_monthly_capacity_reduction(batch_results, calc_results, scenario, calc_ctx, logger) -> (float, dict)`

提取月度加工能力折减逻辑（停工区间合并 + 三档折减 + batch_ratios 记录）。

```python
def _apply_monthly_capacity_reduction(
    batch_results: List[dict],
    calc_results: List[dict],
    scenario: RefineryScenario,
    calc_ctx: Optional[CalcContext] = None,
    logger=None,
) -> Tuple[float, Dict[str, float]]:
    """月度加工能力折减：按装置顺序累计原料量，超容部分按比例折减收益。

    返回:
        (deduction_amount, batch_ratios)
        - deduction_amount: 折减总金额（从 total_revenue 中扣减）
        - batch_ratios: {batch_id: ratio} 每批次折减比例
    """
    # 1. 聚合每装置的停工区间
    device_shutdowns: Dict[str, list] = {}
    for calc in calc_results:
        du = calc.get('device_utilization', {})
        for dev_id, dev in du.items():
            if dev.get('type') == 'start':
                continue
            intervals = du.get('_shutdown_intervals', [])
            if intervals:
                merged = merge_intervals(intervals)
                device_shutdowns.setdefault(dev_id, []).extend(merged)

    # 2. 按装置顺序累计原料量 + 三档折减
    batch_ratios = {br.get('batch_id', ''): 1.0 for br in batch_results}
    total_deduction = 0.0

    for dev_id in (calc_ctx.device_order if calc_ctx else []):
        if dev_id == scenario.start_device_id:
            continue
        dev = scenario.devices.get(dev_id)
        if not dev or dev.type == 'tank':
            continue

        monthly_cap = dev.safety_stock_thrd * (dev.refinery_unit_load_percent or 100) / 100
        if monthly_cap <= 0:
            continue

        # 按批次顺序累计该装置进料量
        cumulative = 0.0
        shutdowns = device_shutdowns.get(dev_id, [])
        effective_days = ...  # 从 batch_results 聚合
        monthly_cap_total = monthly_cap * effective_days

        for br in batch_results:
            batch_id = br.get('batch_id', '')
            inflow = br.get('device_inputs', {}).get(dev_id, 0)
            cumulative += inflow

            if cumulative <= monthly_cap_total:
                continue  # 全加工
            elif cumulative - inflow < monthly_cap_total:
                # 部分加工
                over_ratio = (cumulative - monthly_cap_total) / inflow
                batch_ratios[batch_id] = 1.0 - over_ratio
                total_deduction += br.get('revenue', 0) * over_ratio
            else:
                # 加工不完
                batch_ratios[batch_id] = 0.0
                total_deduction += br.get('revenue', 0)

    return total_deduction, batch_ratios
```

- `evaluate_combination` L1328-1437 → 调用 `_apply_monthly_capacity_reduction(...)`，用返回值扣减 `total_revenue` 并记录 `batch_ratios`
- `recompute_combination_economics` L1693-1770 → 同上

#### 2.2.2 calc_ctx 污染风险

第一轮重构创建了 `calc_ctx` 用于承载从 scenario 剥离的缓存。但若简单地把引用数据（价格、成本、配比）也塞进 calc_ctx，会产生新的"god parameter"问题——函数签名依然是 `calc_ctx: Optional[CalcContext] = None`，依然分不清函数需要价格、成本还是进料配比。

### 核心原则

**calculation 层是纯计算层：给定显式输入 → 产出确定输出，不查 DB、不查缓存。**

数据分三类，处理方式不同：

| 数据类型 | 例子 | 特征 | 正确做法 |
|----------|------|------|----------|
| **引用数据** | prices, device_costs, feed_ratios | 外部 DB 数据，函数自身无法产生 | **显式必传参数**（Service 预加载） |
| **派生中间** | device_order, main_feed_yr, target_flow_map | 从 scenario 就能算出来 | **消除缓存，每次重算**（开销 <1ms） |
| **结果缓存** | physical_cache, econ_cache, hangmei_precompute_cache | 完整计算结果 | **Service 层 cache-aside**（calculation 不感知） |

### 目标架构

```
Service 层（数据获取 + 缓存 + 编排）
┌─────────────────────────────────────────────┐
│ 1. 预加载引用数据:                            │
│    prices = repo.preload_prices(...)         │
│    costs = repo.load_device_costs(...)       │
│    ratios = repo.get_feed_ratio(...)         │
│                                              │
│ 2. cache-aside（结果缓存）:                   │
│    if key in physical_cache:                 │
│        result = physical_cache[key]          │
│    else:                                     │
│        result = calculate_physical(...)      │
│        physical_cache[key] = result          │
│                                              │
│ 3. 组装显式参数，调用 calculation 层           │
└─────────────────────────────────────────────┘
         │ 显式参数（无 calc_ctx）
         ▼
Calculation 层（纯计算）
┌─────────────────────────────────────────────┐
│ calculate_physical(scenario, input, mode,    │
│   days, ...,                                │
│   prices,          ← 显式必传引用数据         │
│   device_costs,    ← 显式必传引用数据         │
│   feed_ratios)     ← 显式必传引用数据         │
│                                             │
│ → 返回结果，不缓存、不查DB、无副作用          │
└─────────────────────────────────────────────┘
```

##### 2.1.4 `build_hangmei_context` + `_preload_all_prices` 合并到 Service

**当前**：两处分别调用 `RefineryRepository().preload_prices()`，重复且分散在 calculation 层。

```python
# solve_service.py
def _preload_reference_data(self, batches, scenario_cache, plan_month):
    """统一预加载引用数据（价格 + 成本 + 配比）。"""
    # 1. 产品价格
    product_ids = set()
    for batch in batches:
        scenario = scenario_cache.get(batch.get('crude_type'))
        if scenario:
            product_ids.update(scenario.products.keys())
    prices = self._refinery_repo.preload_prices(list(product_ids), plan_month)

    # 2. 装置成本
    device_costs = self._refinery_repo.load_device_costs(plan_month)

    # 3. 进料配比
    feed_ratios = {}
    for batch in batches:
        crude_type = batch.get('crude_type')
        if crude_type not in feed_ratios:
            scenario = scenario_cache.get(crude_type)
            if scenario:
                ratios = {}
                for proc_id in scenario.processing_device_ids:
                    ratios[proc_id] = self._refinery_repo.get_feed_ratio(proc_id, crude_type)
                feed_ratios[crude_type] = ratios

    return prices, device_costs, feed_ratios
```

#### 2.2 派生中间缓存 → 消除（每次重算）

6 个派生缓存从 calc_ctx 中移除，calculate_physical 内部每次从 scenario 内存数据重算（不涉及 DB 查询，开销极低）：

| 缓存字段 | 重算逻辑 | 数据来源 | 数据规模 | 重算开销 |
|----------|----------|----------|----------|----------|
| device_order | BFS 遍历 scenario.connections | 内存 dict | ~25 节点 | <0.5ms |
| main_feed_yr_cache | 遍历 scenario.products 取 max yield_rate | 内存 dict | ~50 产品 | <0.3ms |
| target_flow_map_cache | 遍历 scenario.material_flows 构建 tuple→id 映射 | 内存 dict | ~30 物流 | <0.3ms |
| tank_mapping_cache | 遍历 scenario.connections 构建 tank→devices 映射 | 内存 dict | ~15 罐 | <0.2ms |
| tank_flow_mapping_cache | 遍历 scenario.material_flows 构建 tank→flows 映射 | 内存 dict | ~30 物流 | <0.3ms |
| resolve_total_feed_cache | 遍历 scenario.material_flows 查匹配物流 | 内存 dict | ~30 物流 | <0.1ms |

> **注意**：这 6 个缓存的数据全部来自 scenario 对象的内存属性（connections / products / material_flows），scenario 由 Service 层加载后传入，calculation 层只是从这些内存 dict 做一次遍历构建派生映射。**不涉及任何 DB / HTTP 调用**。消除缓存后每次重算的开销 <1ms，对性能无可感知影响。

**消除方式**：在 calculate_physical 内部直接计算，不再检查/写入 calc_ctx。

```python
# 重构前（缓存模式）
if calc_ctx.device_order is None:
    device_order = _build_bfs(scenario)
    calc_ctx.device_order = device_order
else:
    device_order = calc_ctx.device_order

# 重构后（直接计算）
device_order = _build_bfs(scenario)  # <0.5ms，无需缓存
```

#### 2.3 结果缓存 → Service 层 cache-aside

3 个结果缓存从 calculation 层移到 Service 层，calculation 函数不感知缓存：

| 缓存 | 当前位置 | 重构后位置 | 管理方式 |
|------|----------|-----------|----------|
| physical_cache | evaluate_combination 参数 | Service 层 | cache-aside: 命中→直接用，未命中→调 calculate_physical 并存储 |
| econ_cache | evaluate_combination 参数 | Service 层 | cache-aside: 命中→直接用，未命中→调 generate_explanation 并存储 |
| hangmei_precompute_cache | evaluate_combination 参数 | Service 层 | cache-aside: 命中→直接用，未命中→调 _precompute_hangmei_yields 并存储 |

**当前模式**（calculation 层管理缓存）：
```python
# evaluate_combination 内部
for batch in batches:
    key = (crude_type, mode, input, days)
    if key in physical_cache:          # ← 缓存逻辑在 calculation 层
        result = physical_cache[key]
    else:
        result = calculate_physical(...)
        physical_cache[key] = result   # ← 缓存写入在 calculation 层
```

**目标模式**（Service 层 cache-aside）：
```python
# Service 层
for batch in batches:
    key = (crude_type, mode, input, days)
    if key in physical_cache:
        physical_results.append(physical_cache[key])
    else:
        result = calculate_physical(..., feed_ratios=feed_ratios)
        physical_cache[key] = result
        physical_results.append(result)

# 传入预计算结果，evaluate_combination 不再管缓存
evaluate_combination(combo, batches, physical_results=physical_results, ...)
```

**注意**：这要求 evaluate_combination 签名变更——接受预计算的 physical_results 而非内部调用 calculate_physical。这是 Phase 4（拆分 calculate_physical）和 Phase 1（抽取公共函数）的自然延伸。

```python
def _build_topology(scenario: RefineryScenario) -> List[str]:
    """BFS 拓扑排序（每次重算，<0.5ms，无需缓存）。"""
    device_order = []
    visited = set()
    queue = [scenario.start_device_id]
    visited.add(scenario.start_device_id)

    while queue:
        device_id = queue.pop(0)
        device_order.append(device_id)
        downstream_conns = [conn for conn in scenario.connections.values()
                            if conn.from_device_id == device_id]
        for conn in downstream_conns:
            to_device_id = conn.to_device_id
            if to_device_id not in visited:
                visited.add(to_device_id)
                queue.append(to_device_id)

    for device_id in scenario.devices:
        if device_id not in visited:
            device_order.append(device_id)

    return device_order
```

```python
def _init_special_vars(yield_mode: str, input_amount: float,
                       scenario: RefineryScenario) -> dict:
    """计算 jian1 理论总量并设置特殊变量 X/Y。"""
    cdu_id = scenario.cdu_device_id
    jian1_product = scenario.products.get(f"{cdu_id}_jian1") if cdu_id else None
    jian1_yield = jian1_product.yield_rate if jian1_product else 0
```

```python
def calculate_physical(scenario, input_amount, yield_mode, logger=None,
                       total_input_amount=None, days=1, hangmei_mode=False,
                       hangmei_m_days=0, day_index=0, shutdown_intervals=None,
                       feed_ratios: Dict[str, Dict[str, float]] = None) -> Tuple[bool, dict]:
    """纯物理计算（不含经济计算/价格参数）。

    Args:
        feed_ratios: 按 {crude_type: {proc_id: ratio}} 预加载的进料配比，由 Service 层传入。
    """
    if logger is None:
        logger = get_logger()

    try:
        special_vars = _init_special_vars(yield_mode, input_amount, scenario)
        if special_vars is None:
            return False, {'message': f'不支持的模式: {yield_mode}'}

        device_order = _build_topology(scenario)
        final_device_inputs, main_feed_totals, total_feeds, connection_flows = \
            _forward_traverse(scenario, device_order, input_amount, special_vars,
                              feed_ratios, logger)
        _fix_cross_edges(scenario, device_order, final_device_inputs, total_feeds,
                         connection_flows, logger)
        _apply_shutdown_scaling(final_device_inputs, connection_flows,
                                shutdown_intervals, days, scenario, logger)
        device_utilization = _build_device_utilization(
            scenario, final_device_inputs, connection_flows, days, special_vars)

        result = {
            'device_inputs': final_device_inputs,
            'main_feed_totals': main_feed_totals,
            'total_feeds': total_feeds,
            'connection_flows': connection_flows,
            'special_vars': special_vars,
            'device_utilization': device_utilization,
            'input_amount': total_input_amount if total_input_amount is not None else input_amount,
            'feasible': True,
            'bottleneck_devices': [],
        }
        return True, result
    except Exception as e:
        logger.error(f"[{yield_mode}] 直接计算失败: {e}")
        import traceback
        logger.error(traceback.format_exc())
        return False, {'message': f'直接计算失败: {str(e)}'}
```
