# 炼化可行性规则字典

> **用途**：本文档供 Agent 平台（Dify/Coze/LangGraph/Trae 等）导入为知识库，指导 Agent 如何将用户自然语言约束翻译为 `assess_feasibility`（MCP-15）的 `rules` 参数。

## MCP-15 工具签名

```
assess_feasibility(combination_results: list, rules: dict = None) -> dict
```

- `combination_results`：来自 MCP-06（optimize_combinations）的 `combination_results` 字段
- `rules`：规则参数 dict，不传时使用默认规则

## 规则字段定义

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `max_load_rate` | float | 100.0 | 月度平均负荷率上限（百分比）。超过此值的装置计入超容 |
| `tank_capacity_strict` | bool | True | 罐容违规是否作为硬约束。True=违规即不可行，False=仅标记不否决 |
| `max_overload_count` | int | 0 | 允许的超容装置数量上限。超过此数则判不可行 |
| `max_overload_ratio` | float | 0.0 | 允许的超容比例（百分比）。如 10.0 表示允许超容到 110% |
| `min_hangmei_output` | float | 0.0 | 航煤最低产出约束（吨）。低于此值判不可行 |
| `require_all_feasible` | bool | False | 是否要求所有批次均可行。True=任一批次不可行则组合不可行 |

## 判定逻辑

```
1. 罐容检查
   tank_strict=True 且 violation_count > 0 → 不可行

2. 负荷检查
   超容装置数 > max_overload_count → 接近可行（near_feasible）
   超容比例 > max_overload_ratio → 严重超容

3. 航煤检查（仅启用航煤工况时）
   航煤产出 < min_hangmei_output → 不可行

4. 批次检查
   require_all_feasible=True 且存在不可行批次 → 不可行

5. 综合判定
   有硬约束违规 → 不可行
   超容但无硬约束违规 → 接近可行
   无任何违规 → 可行
```

## 用户意图 → rules 映射

| 用户表述 | rules_json |
|----------|-----------|
| "减一线不能超负荷" | `{"max_load_rate": 95.0}` |
| "允许小幅超容到105%" | `{"max_load_rate": 105.0}` |
| "罐容这周紧张" | `{"tank_capacity_strict": true}` |
| "罐容可以灵活处理" | `{"tank_capacity_strict": false}` |
| "允许1台装置超容" | `{"max_overload_count": 1}` |
| "航煤保供5000吨" | `{"min_hangmei_output": 5000}` |
| "所有批次必须可行" | `{"require_all_feasible": true}` |
| "严格模式（全部收紧）" | `{"max_load_rate": 95.0, "tank_capacity_strict": true, "max_overload_count": 0}` |
| "宽松模式（允许超容）" | `{"max_load_rate": 110.0, "tank_capacity_strict": false, "max_overload_count": 2}` |

```json
  }

```

## 组合调用示例

```
1. MCP-06: optimize_combinations → 获取 combination_results
2. MCP-15: assess_feasibility(combination_results, rules) → 获取可行性判定
3. MCP-16: select_optimal(combination_results, strategy) → 选最优
```
